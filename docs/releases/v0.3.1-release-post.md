## Long Post

```md
Quaid v0.3.1 is out.

This is the first installable public release of Quaid.

Quaid is a long-term memory system for coding agents. It is built for the
failure mode that shows up once an agent stops living inside a single context
window: resets happen, sessions end, project state drifts, and important facts
get buried under raw transcript history.

Quaid addresses that by giving the agent a memory layer that persists across
sessions and keeps itself maintained over time.

At a high level, the system does four things:

1. It extracts durable facts from conversations and runtime activity instead of
   relying on the full transcript forever.
2. It maintains evolving identity state through per-instance `SOUL.md`,
   `USER.md`, and `ENVIRONMENT.md` files.
3. It tracks project documentation separately from personal memory and keeps it
   available through the docs/RAG pipeline.
4. It runs background maintenance so memory can be reviewed, deduplicated,
   decayed, and distilled rather than only appended to.

The result is a memory system that is meant to stay operational over time, not
just look good in a short demo.

v0.3.1 is the first installable public cut of that system. It includes:

- the core memory engine
- per-instance silos for host integrations
- project registry and docs indexing
- recall and retrieval pipelines
- evolving identity files
- janitor maintenance
- host adapters for OpenClaw, Claude Code, and Codex
- a shared credential store so later platform installs can reuse the first
  configured auth instead of prompting lane-by-lane

Current host support:

- OpenClaw: the most complete integration today, including the strongest
  compaction-control path
- Claude Code: stable memory and hook path, but no timeout-based compaction
  control
- Codex: stable memory path, but hook-injected context is currently visible in
  the host view and can feel noisy

Anthropic-backed lanes are the recommended default. OpenAI-backed
lanes remain available for users who need them, but current benchmark and live
results show a meaningful quality drop. Release messaging should be explicit
about that tradeoff rather than implying parity.

This release is installable, but it is not the end of the hardening work. The main
known limitations right now are:

- OpenClaw is still the most mature host path
- Windows is not supported yet
- multi-user behavior is not fully hardened under heavy concurrency
- some parallel-session and lifecycle edge cases still exist

If you want the detailed change list, read the release notes:

If you want the repo and install entrypoint:
<repo-link>
```
