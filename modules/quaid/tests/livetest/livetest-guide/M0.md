# M0: First Install

Purpose: validate that Quaid installs cleanly from scratch. This is a first-install
test — "reinstall" is never right, since we always start from a wiped workspace.
Three independent install paths exist and M0 exercises whichever one the
coordinator chose for the run:

- **install-all** — the coordinator's `--all-platforms` installer, one invocation
  sets up every enabled platform in one pass.
- **CLI per-platform** — the tester runs `setup-quaid.mjs` directly for one
  platform, exactly the way a human would if they were scripting the install.
- **Agent-driven per-platform** — the tester hands a minimal natural-language
  prompt to the platform agent and lets the agent read `AI-INSTALL.md` and
  execute the install itself.

The coordinator tells the lane which path to run. A full run usually rotates
through all three over successive runs so each path gets exercised.

## Preconditions (handled by preflight)

Before M0 runs, `livetest-preflight.sh` has already:

- wiped `~/.quaid`, the OC plugin extension dir, and per-platform caches on
  the remote
- rsynced the current dev tree to the remote
- seeded `~/.quaid/shared/auth/credentials.json` with the shared Quaid
  authentication credential
- seeded the CC `claude` CLI credential
- started the platform services

Do not run install commands before M0 — the whole point is that M0 is the
first install.

## Lane order

Only one platform runs its M0 install at a time (install touches shared host
state). Once a platform's M0 passes, the next platform's tester starts. Once
all lane M0s pass, parallel M1+ execution begins.

## Path A — install-all (coordinator mode)

Coordinator invokes the `--all-platforms` installer directly. Testers do not
run their own installer in this mode; they only verify the result.

```bash
ssh REMOTE_HOST 'source ~/.zprofile >/dev/null 2>&1; cd ~/quaidcode/dev && \
  QUAID_ALLOW_DEV_INSTALL=1 node setup-quaid.mjs \
  --all-platforms --owner-name OWNER_NAME --agent 2>&1 | tail -80'
```

Then each tester runs the "verify install quality" checks below for its lane.

## Path B — CLI per-platform (tester mode)

The tester exercises the command-line installer directly. Do not treat this
as a "dry-run for handoff" — it is the actual install.

```bash
# Replace ADAPTER with openclaw | claude-code | codex
ssh REMOTE_HOST 'source ~/.zprofile >/dev/null 2>&1; cd ~/quaidcode/dev && \
  QUAID_ALLOW_DEV_INSTALL=1 node setup-quaid.mjs \
  --adapter ADAPTER --owner-name OWNER_NAME --agent 2>&1 | tail -60'
```

Do not set `QUAID_INSTANCE` — instances are path-derived on first use. If
this is not the first platform installed this run, add `--add-platform`.

## Path C — Agent-driven per-platform (tester mode)

The tester passes the platform agent a minimal natural-language install
request — the kind of message a real user would send — and lets the agent
figure out the rest by reading `AI-INSTALL.md`. The agent is "the user" here;
it has access to everything a user would, including credentials already
seeded by preflight.

Tester message to the platform agent (verbatim, no extras):

> Check out Quaid at `~/quaidcode/dev` — can you install it? Owner name:
> OWNER_NAME. Install from the local checkout (not a release build).

If the agent asks for a credential, the agent should locate and use the
already-seeded `~/.quaid/shared/auth/credentials.json` and / or its platform
OAuth file — not relay a prompt back to you. If the agent cannot complete
the install from this minimum prompt, the failure is a bug in `AI-INSTALL.md`
and should be filed as such; do not coach the agent through the steps.

Answer clarifying questions naturally if the agent asks something a human
user would reasonably answer. Do not supply installer commands, flag names,
or env var names.

## Verify install quality

Every path ends in the same state. Run these checks once the install returns:

- `quaid doctor` returns healthy (exit 0, no CRITICAL warnings).
- `~/.quaid/instances/<instance_id>/data/memory.db` exists and is non-empty
  after the first hook fires.
- Hook registrations present in the platform's config (platform guide lists
  the exact file).
- A basic agent turn succeeds without hanging.
- No orphan install lock (`~/.quaid/.installer.lock`) remaining.

## Pass / Fail

**PASS:** the chosen install path completes, `quaid doctor` is healthy,
artifacts exist at expected paths, a basic turn works.

**FAIL:** the install could not complete, a silent partial install, or
`quaid doctor` errors. Post ISSUE with the full pane capture.

Platform-specific hangs, model rejections, and other quirks live in the
platform supplements (`TESTER.OC.md`, `TESTER.CC.md`, `TESTER.CDX.md`).
Long installer stalls are not expected — if the install stalls more than a
couple of minutes without progress, post ISSUE.
