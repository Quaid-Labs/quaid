# M1: Supervisor and Monitor Runtime Stability

Purpose: validate the supervisor, daemon monitor, project-docs worker, janitor
worker, and transient SQLite setup-lock retry paths. This milestone runs FIRST
on every lane because if the supervisor and monitor are not healthy, every
later milestone will fail in confusing ways.

This milestone is coordinator-observed. Do not grade it from the agent's visible
answer alone. A clean pass requires process, status, signal, and log evidence.

## Setup

Your platform supplement defines the per-lane variables you need:

- `INSTANCE` — the lane's instance id.
- `QCLI` — absolute path to the `quaid` CLI binary for that lane.
- `SILO` — absolute path to the lane's instance directory
  (`~/.quaid/instances/<INSTANCE>`).
- `LIFECYCLE` — the lane's "end-of-session" command (`/new`, `/reset`, `/clear`).
- `SEND` — the send mechanism (Matrix script for OC, visible pane for CC/CDX).

Everything below uses those variables. Do not hard-code paths.

Create an artifact directory for this probe's evidence:

```bash
LANE_UPPER=$(printf "%s" "$LANE" | tr '[:lower:]' '[:upper:]')
PROBE_ID="M1-${LANE_UPPER}-SUP-$(date +%Y%m%d-%H%M%S)"
ART="$HOME/m1-artifacts/$PROBE_ID"
mkdir -p "$ART"
echo "$PROBE_ID"  > "$ART/probe-id.txt"
echo "$INSTANCE"  > "$ART/instance.txt"
```

Canary phrase (used by SUP-02): `<LANE_UPPER> supervisor m1 cobalt-postage`.
The `cobalt-postage` string is a shared marker across platforms; prefix with
the upper-case lane so the same keyword can find the per-platform fact.

## SUP-00: Pre-state capture

```bash
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon status --json \
  > "$ART/status-before.json" 2>&1 || true
ps auxww | grep -E 'extraction_daemon|project_docs_supervisor|project_docs_worker|janitor' \
  | grep -v grep > "$ART/ps-before.txt" || true
ls -1 "$SILO/data/extraction-signals/"* 2>/dev/null | sort > "$ART/signals-before.txt" || true
tail -200 "$SILO/logs/daemon/extraction-daemon.log"       > "$ART/extraction-daemon-before.log" 2>&1 || true
tail -200 "$SILO/logs/daemon/project-docs-supervisor.log" > "$ART/docs-supervisor-before.log"   2>&1 || true
tail -200 "$SILO/logs/daemon/rolling-extraction.jsonl"    > "$ART/rolling-before.jsonl"          2>&1 || true
```

## SUP-01: Bootstrap and monitor health

Restart the lane daemon so the probe starts from a known state:

```bash
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon stop  2>&1 | tee "$ART/daemon-stop.txt" || true
sleep 2
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon start 2>&1 | tee "$ART/daemon-start.txt"
sleep 10
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon status --json \
  > "$ART/status-after-start.json" 2>&1
ps auxww | grep -E 'extraction_daemon|project_docs_supervisor|project_docs_worker|janitor' \
  | grep -v grep > "$ART/ps-after-start.txt" || true
```

**Pass:**

- `daemon status --json` reports `running=true`.
- The pid file in `$SILO/data/` points to a live process.
- Supervisor or monitor process is present when expected.
- No duplicate respawn loop for the same instance after 30 seconds.

**Fail:**

- `running=false` after start.
- pid file is absent or stale.
- supervisor exits immediately.
- multiple replacement daemons appear without an explicit restart.

## SUP-02: Hook-driven survival after real work

Send a normal user turn with the canary, wait, then fire `LIFECYCLE`:

```text
M1 supervisor canary: <LANE_UPPER> supervisor m1 cobalt-postage. Remember
that my workshop checklist includes polishing the brass gauge every Friday.
```

Wait ~20 s, then send `LIFECYCLE`. After the lifecycle completes:

```bash
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon status --json \
  > "$ART/status-after-hook.json" 2>&1 || true
ps auxww | grep -E 'extraction_daemon|project_docs_supervisor|project_docs_worker|janitor' \
  | grep -v grep > "$ART/ps-after-hook.txt" || true
ls -1 "$SILO/data/extraction-signals/"* 2>/dev/null | sort > "$ART/signals-after-hook.txt" || true
tail -300 "$SILO/logs/daemon/extraction-daemon.log" > "$ART/extraction-daemon-after.log" 2>&1 || true
tail -300 "$SILO/logs/daemon/rolling-extraction.jsonl" > "$ART/rolling-after.jsonl" 2>&1 || true
```

**Pass:**

- Supervisor and daemon survive the lifecycle boundary; no respawn storm.
- Extraction signals drain (signals-after-hook shows fewer, not more).
- The canary keyword appears in `memory.db` via FTS match or `quaid recall`.

**Fail:**

- Supervisor dies and does not restart.
- Signals accumulate without draining.
- Canary keyword never lands in `memory.db`.

## SUP-03: Status-burst stress

Rapid successive status checks must not disturb the supervisor or leave lock
files behind:

```bash
for i in $(seq 1 20); do
  QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon status --json \
    >/tmp/m1-status-$LANE-$i.json 2>/tmp/m1-status-$LANE-$i.err || true
  QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" health \
    >/tmp/m1-health-$LANE-$i.txt 2>/tmp/m1-health-$LANE-$i.err || true
done
QUAID_HOME=$HOME/.quaid QUAID_INSTANCE="$INSTANCE" "$QCLI" daemon status --json \
  > "$ART/status-after-burst.json" 2>&1 || true
```

**Pass:**

- All 20 status calls complete without error.
- No SQLite "database is locked" lines in `$SILO/logs/daemon/*.log` after the
  burst.
- Daemon is still `running=true` afterwards.

## SUP-04: Cross-instance isolation

If any other lane has already installed, confirm that this lane's daemon did
not attach to another lane's silo:

```bash
ps auxww | grep -E 'extraction_daemon|project_docs_supervisor' | grep -v grep \
  > "$ART/ps-all-instances.txt" || true
```

**Pass:** every running supervisor / daemon line references **this** instance's
`$SILO` path, not another lane's silo.

**Fail:** a process in the list references a foreign instance directory — this
is a cross-instance contamination regression and is a blocker for all later
milestones.
