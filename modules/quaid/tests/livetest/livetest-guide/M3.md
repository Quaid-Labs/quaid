# M3: Project System + Docs CLI

Purpose: validate the project-system CRUD surfaces and the docs/health/session CLI in one pass.
Depends on M0 having installed cleanly.

This is a merge of the old M8 (project CRUD) and M10 (docs/health/session CLI). Run both parts.

## Pass (both parts)

- Part A: create/link/show/update/sync/delete flow succeeds end-to-end; stale entries are cleaned;
  delete tombstone holds across sync.
- Part B: `quaid docs list/update/check/changelog`, `quaid doctor`, and session-management CLIs
  return expected results for the installed state.
- No orphan files, stale registry rows, or ghost worker processes after the sequence.

## Part A — Project system CRUD

1. **Create.**
   ```bash
   ssh REMOTE_HOST 'quaid project create livetest-demo --description "M3 demo project" --source-root /tmp/livetest-demo-src'
   ```
   Expect: project row created, project directory scaffolded under
   `~/quaid/projects/livetest-demo/`.

2. **Register a doc.** Create a temp file, register it:
   ```bash
   ssh REMOTE_HOST 'mkdir -p /tmp/livetest-demo-src && echo "Ember Glass is a type of copper-tinted laminated pane." > /tmp/livetest-demo-src/emberglass.md'
   ssh REMOTE_HOST 'quaid registry register /tmp/livetest-demo-src/emberglass.md --project livetest-demo'
   ```
   Expect: registered without error; doc appears in `quaid docs list --project livetest-demo`.

3. **Update via `docs update --apply`.**
   ```bash
   ssh REMOTE_HOST 'quaid docs update --apply --project livetest-demo'
   ```
   Expect: indexing completes, PROJECT.log has a fresh entry, no ImportError.

4. **Show + update metadata.**
   ```bash
   ssh REMOTE_HOST 'quaid project show livetest-demo'
   ssh REMOTE_HOST 'quaid project update livetest-demo --description "updated"'
   ssh REMOTE_HOST 'quaid project show livetest-demo'
   ```

5. **Sync.**
   ```bash
   ssh REMOTE_HOST 'quaid project sync'
   ```
   Expect: sync completes; the test project is still listed.

6. **Delete.**
   ```bash
   ssh REMOTE_HOST 'quaid project delete livetest-demo'
   ```
   Expect:
   - Project row removed from the registry.
   - Project directory removed from `~/quaid/projects/`.
   - Docs workers for this project stop cleanly (no respawn after 30 s).
   - A subsequent `quaid project sync` does not resurrect the project.
   - Docs registry read returns no rows for `project=livetest-demo`.

7. **Verify no misc resurrection.** List agent instances:
   ```bash
   ssh REMOTE_HOST 'quaid instances list --json'
   ```
   Any `misc--*` rows associated with the deleted project must also be gone.

## Part B — Docs, Health, and Session CLI

1. **Doctor.**
   ```bash
   ssh REMOTE_HOST 'quaid doctor'
   ```
   Expect: exit 0. No CRITICAL findings. Model resolution lines show configured fast/deep models.
   Compatibility circuit breaker reports `normal` (not `degraded`).

2. **Docs list.**
   ```bash
   ssh REMOTE_HOST 'quaid docs list'
   ssh REMOTE_HOST 'quaid docs list --project quaid'
   ```
   Expect: both return rows; unscoped list is a superset of scoped.

3. **Docs check (stale detection).**
   ```bash
   ssh REMOTE_HOST 'quaid docs check'
   ```
   Expect: returns without error. Lists any known-stale docs.

4. **Docs changelog.**
   ```bash
   ssh REMOTE_HOST 'quaid docs changelog --project quaid --limit 5'
   ```
   Expect: returns recent PROJECT.log entries for the quaid project.

5. **Session-management CLI spot check (CC lane only).** CC tracks sessions under
   `/tmp/cc-livetest`. Confirm the current session is listed and that `--json` output parses:
   ```bash
   ssh REMOTE_HOST 'quaid stats --json | python3 -m json.tool | head -20'
   ```

## PWN vs FAIL

- `docs list` returns stale entries for a filesystem-deleted file → PWN-note; the delete-propagation
  gap is tracked, not an M3 block.
- `quaid project sync` slow on first run → PWN-note with timing.
- `quaid doctor` reports LOW-severity findings with exit 0 → PASS.
- `quaid project delete` leaves zombie worker processes or resurrects on sync → FAIL.
- `quaid doctor` exits nonzero or reports CRITICAL / missing config → FAIL.
