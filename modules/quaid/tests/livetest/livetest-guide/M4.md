# M4: Janitor + Generated Artifacts

Purpose: validate the janitor review cycle plus the snippet/journal/project-log generation that the
janitor drives. Old M9 (Janitor) and M11 (Snippet/Journal/Project Log Generation) were tightly
cross-fed — janitor is what graduates pending facts and emits snippets — so they live in one
milestone with parts.

## Pass (both parts)

- Dry-run completes within ~60 s and reports a non-empty plan.
- `--apply` completes (first run can take 15–30 minutes due to LLM review of accumulated memories);
  state advances: pending → approved on reviewed rows.
- Snippets, journals, and PROJECT.log entries appear in visible home (`~/quaid/`) with fresh
  timestamps matching the apply window.
- No duplicate or orphan snippet/journal rows; registry deletes propagate (see Part B audit).

## Part A — Janitor

Depends on M1 having stored at least a handful of facts.

1. **Record baseline line counts** so you can confirm condensation:
   ```bash
   ssh REMOTE_HOST 'for f in ~/quaid/identity/SOUL.md ~/quaid/identity/USER.md ~/quaid/identity/ENVIRONMENT.md; do echo -n "$f: "; wc -l < "$f" 2>/dev/null || echo "(missing)"; done'
   ```
2. **Dry-run.**
   ```bash
   ssh REMOTE_HOST 'timeout 90 quaid janitor --task all --dry-run 2>&1 | tail -40'
   ```
   Expect: completes in ≤60 s. Hang here = regression in dry-run LLM/checkpoint bypass.
3. **Apply.**
   ```bash
   ssh REMOTE_HOST 'quaid janitor --task all --apply --approve 2>&1 | tail -40'
   ```
   Expect: completes; "vec_nodes upsert recovered" / "snippet remap" lines are normal. If it appears
   stuck for >30 min with no log progress, capture logs and ISSUE.
4. **Verify review state advanced.** Pending → approved on reviewed rows:
   ```bash
   ssh REMOTE_HOST 'sqlite3 ~/.quaid/instances/<INSTANCE>/data/memory.db \
     "SELECT status, COUNT(*) FROM nodes GROUP BY status;"'
   ```
   Expect: non-zero `approved` count, and the count grew vs. pre-apply.

## Part B — Snippet, Journal, and Project Log Generation

This runs as part of the janitor apply, but verification checks a different set of files and a
different registry.

1. **Snippets** appear under `~/quaid/identity/<SOUL|USER|ENVIRONMENT>.snippets.md` with a dated
   heading matching the apply window. Spot-check at least one:
   ```bash
   ssh REMOTE_HOST 'tail -30 ~/quaid/identity/SOUL.snippets.md'
   ssh REMOTE_HOST 'tail -30 ~/quaid/identity/USER.snippets.md'
   ssh REMOTE_HOST 'tail -30 ~/quaid/identity/ENVIRONMENT.snippets.md'
   ```
2. **Journals** appear under `~/quaid/journals/`:
   ```bash
   ssh REMOTE_HOST 'ls -la ~/quaid/journals/ | head -10'
   ssh REMOTE_HOST 'tail -30 ~/quaid/journals/SOUL.md ~/quaid/journals/USER.md ~/quaid/journals/ENVIRONMENT.md 2>/dev/null | head -40'
   ```
3. **PROJECT.log** for the `quaid` project gets a new entry dated today:
   ```bash
   ssh REMOTE_HOST 'tail -10 ~/quaid/projects/quaid/PROJECT.log'
   ```
4. **Line-count diff** (compare to Part A step 1). Folded files should have grown by snippet rows;
   SOUL/USER/ENVIRONMENT may show condensation if the janitor rewrote older folded sections.

## PWN vs FAIL

- Apply takes >30 min but completes — PWN-note with timing; not a FAIL unless hung.
- `snippet remap` warnings, `vec_nodes upsert recovered` lines — noise, not failure.
- Snippet / journal path deviates between visible/hidden homes (tester hits the wrong one) —
  PWN-note path deviation.
- Dry-run hangs >60 s — FAIL (regression in checkpoint bypass).
- Apply completes but no state advances (still all pending) — FAIL.
- Snippets / journals / PROJECT.log entries never materialize after apply — FAIL.
