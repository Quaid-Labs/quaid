# M4: Project System and Docs CLI

Purpose: validate the project-system CRUD surfaces and the docs / health /
session CLI. Covers both the end-to-end project lifecycle and the
verification tools that inspect what the system thinks it has stored.

## Shared fixture

M4 uses the sample project at `data/test-project/` — a small Python
"agent-messaging" package that gives docs-recall and TOOLS.md population
something real to work with. When registering into Quaid, name the project
`livetest-agentmsg-<LANE>` so concurrent per-platform runs don't collide in
the globally-shared docs index.

## Pass (both parts)

- Part A: create / link / show / update / sync / delete flow succeeds
  end-to-end; stale registry entries are cleaned; delete propagates across a
  subsequent `sync`.
- Part B: `quaid docs list / update / check / changelog`, `quaid doctor`,
  and session-management CLIs return expected results for the installed
  state.
- No orphan files, stale registry rows, or ghost worker processes after the
  sequence.

## Part A — Project-system CRUD

1. **Create.** Register the sample project. Source-root is the fixture
   inside the dev checkout on the remote:

   ```bash
   ssh REMOTE_HOST "\$QCLI project create livetest-agentmsg-\$LANE \
     --description 'agentmsg livetest fixture' \
     --source-root ~/quaidcode/dev/modules/quaid/tests/livetest/livetest-guide/data/test-project"
   ```

2. **Link source files.**

   ```bash
   ROOT=~/quaidcode/dev/modules/quaid/tests/livetest/livetest-guide/data/test-project
   for f in README.md agentmsg/__init__.py agentmsg/api.py agentmsg/examples.md; do
     ssh REMOTE_HOST "\$QCLI registry register $ROOT/$f \
       --project livetest-agentmsg-\$LANE"
   done
   ```

   Expect: all four files registered without error; they appear in
   `quaid docs list --project livetest-agentmsg-$LANE`.

3. **Index.** The daemon's project-docs worker picks up doc registrations
   automatically, but the test wants a deterministic indexing point:

   ```bash
   ssh REMOTE_HOST "\$QCLI docs update --apply --project livetest-agentmsg-\$LANE"
   ```

   Expect: output names each file indexed. `PROJECT.md` is auto-generated.
   `TOOLS.md` / `AGENTS.md` are updatable-root docs — they are NOT
   auto-generated from source; they are agent-authored over time. For M4,
   confirm only that `PROJECT.md` exists:

   ```bash
   ssh REMOTE_HOST "cat ~/quaid/projects/livetest-agentmsg-\$LANE/PROJECT.md"
   ```

   If `TOOLS.md` / `AGENTS.md` are missing, that's normal for a
   just-registered project — the agent would populate them on first use.

4. **Docs recall probe.** Issue a docs-store recall using the example
   codeword:

   ```bash
   ssh REMOTE_HOST "\$QCLI recall 'cobalt-postage' \
     '{\"stores\":[\"docs\"],\"project\":\"livetest-agentmsg-\$LANE\"}'"
   ```

   Expect: the top hit is `agentmsg/examples.md`.

5. **Update.**

   ```bash
   ssh REMOTE_HOST "\$QCLI project update livetest-agentmsg-\$LANE \
     --description 'updated livetest fixture'"
   ssh REMOTE_HOST "\$QCLI project show livetest-agentmsg-\$LANE"
   ```

   Expect: the new description is returned.

6. **Status.** `project status <name>` returns docs-worker freshness
   (`project sync` does not exist as a CLI surface; use `status` for a
   registry-on-disk consistency check):

   ```bash
   ssh REMOTE_HOST "\$QCLI project status livetest-agentmsg-\$LANE"
   ```

   Expect: no errors; output reports indexed state for the four registered
   files.

7. **Reserved-project protection.** Core-reserved projects must reject
   delete attempts cleanly:

   ```bash
   set +e
   ssh REMOTE_HOST "\$QCLI project delete quaid"
   echo "quaid delete rc=$?"
   ssh REMOTE_HOST "QUAID_INSTANCE=\$INSTANCE \$QCLI project delete misc--\$INSTANCE"
   echo "misc delete rc=$?"
   set -e
   ```

   Expect: both commands exit nonzero and print a clean reserved-project
   error. `quaid` remains present, and `misc--$INSTANCE` remains usable for
   later milestones.

8. **Delete and propagation.** Delete the project and verify it goes away:

   ```bash
   ssh REMOTE_HOST "\$QCLI project delete livetest-agentmsg-\$LANE"
   ssh REMOTE_HOST "\$QCLI project list"
   ```

   Expect: `project list` no longer shows the project. Any `misc--*` rows
   associated with the deleted project must also be gone. The daemon's
   project-docs worker should not resurrect the project entry on its next
   cycle — observe `~/quaid/projects/livetest-agentmsg-<LANE>/` stays
   absent.

9. **Restore for later milestones.** Re-register the fixture so later
   milestones that need a live project have one to work with:

   ```bash
   ssh REMOTE_HOST "\$QCLI project create livetest-agentmsg-\$LANE \
     --description 'agentmsg livetest fixture' \
     --source-root ~/quaidcode/dev/modules/quaid/tests/livetest/livetest-guide/data/test-project"
   ```

   Re-register the source files (step 2) and re-index (step 3).

## Part B — Docs, Health, and Session CLI

1. **Doctor.**

   ```bash
   ssh REMOTE_HOST "\$QCLI doctor"
   ```

   Expect: exit 0, no CRITICAL findings. LOW / INFO findings are acceptable.

2. **Docs inventory.**

   ```bash
   ssh REMOTE_HOST "\$QCLI docs list"
   ssh REMOTE_HOST "\$QCLI docs check"
   ssh REMOTE_HOST "\$QCLI docs changelog --limit 10 --json"
   ```

   Expect: inventory includes the re-registered fixture; `docs check`
   reports any drift; changelog lists the recent register / update events
   across all projects (the CLI only supports `--limit` and `--json`; no
   per-project filter).

3. **Session state (via DB, not CLI).** There is no public `quaid session`
   CLI — session logs are internal runtime plumbing. Verify session state
   directly:

   ```bash
   ssh REMOTE_HOST "sqlite3 ~/.quaid/instances/\$INSTANCE/data/memory.db \
     \"SELECT DISTINCT session_id FROM nodes WHERE session_id IS NOT NULL \
      ORDER BY created_at DESC LIMIT 5;\""
   ```

   Expect: at least one session_id corresponds to M2's rolling / lifecycle
   extraction runs.

## Pass / Fail

- `quaid doctor` exits nonzero or reports CRITICAL findings → FAIL.
- `quaid project delete quaid` or `quaid project delete misc--<instance>`
  succeeds → FAIL.
- `quaid project delete` leaves zombie worker processes, or the project
  reappears after a subsequent `sync` → FAIL.
- `docs update --apply` on a new fixture does not index any file → FAIL.
- `TOOLS.md` auto-generation misses expected symbols → PWN-note; attach the
  generated file for review.
- `docs list` returns stale entries for a filesystem-deleted file →
  PWN-note; note the delete-propagation lag.
