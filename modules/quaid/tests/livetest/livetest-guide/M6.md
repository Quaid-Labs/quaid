# M6: Agent Notifications

Purpose: validate that Quaid surfaces notifications back to the agent via the
hook-inject path — both scheduled / deferred notices and fast-path provider-
outage errors.

## Pass (both parts)

- Part A: a deferred notice (janitor-queued or coordinator-queued) appears in
  the next turn's injected context; a second "dedupe" turn does not repeat
  the same notice.
- Part B: an unreachable LLM provider triggers a provider-error notification
  that surfaces on **every turn where the broken recall / LLM call actually
  fires**. No dedupe or throttle may suppress an actively-firing error.

## Part A — Deferred notification surfacing

Design intent: janitor and other slow background systems write deferred
notices intended for the next time the operator is actually conversing with
the agent. Drain happens on turn boundary only — deferred notices never
auto-drain during autonomous / hook-only paths.

Procedure:

1. Confirm no pending deferred notice:

   ```bash
   ssh REMOTE_HOST "\$QCLI notify --deferred-status"
   ```

   Expect: `pending=0` (or no pending lines).

2. Queue a deferred notice by writing directly to the instance's delayed
   LLM-requests note file:

   ```bash
   ssh REMOTE_HOST 'python3 -c "
   import json, os
   p = os.path.expanduser(\"~/.quaid/instances/$INSTANCE/.runtime/notes/delayed-llm-requests.json\")
   os.makedirs(os.path.dirname(p), exist_ok=True)
   data = json.load(open(p)) if os.path.exists(p) else {\"requests\": []}
   data[\"requests\"].append({
       \"id\": \"m6-partA-\$(date +%s)\",
       \"status\": \"pending\",
       \"kind\": \"janitor_notice\",
       \"message\": \"M6 test notice: scheduled review found 3 facts that may be outdated and need refresh.\",
   })
   json.dump(data, open(p, \"w\"), indent=2)
   print(\"queued\")
   "'
   ```

3. Confirm pending = 1:

   ```bash
   ssh REMOTE_HOST "\$QCLI notify --deferred-status"
   ```

4. Send a natural user turn — e.g. "Hey, what's up?" — through the
   platform's visible interaction surface.

5. Verify the notice appears in the agent's context and the agent's reply
   acknowledges it in plain language.

6. Check the JSON row for the notice: `status=delivered`, `delivered_at`
   populated.

7. **Dedupe turn.** Send "Ready for the next check." Agent should reply
   ready and NOT repeat the notice.

8. Confirm `pending=0` again.

## Part B — Provider outage fast-path

Design intent: provider errors are critical user-facing failures ("your LLM
is broken"). They must not be deduped or throttled for turns where the error
actually fires. Contrast with Part A — janitor summaries are deduped because
janitor fires once per night so the class naturally de-dups itself. Provider
failures fire per-turn and must surface per-turn.

This part uses a platform-scoped broken-model config (not a global credential
swap). Pointing one instance's model config at a nonexistent model name
breaks only that lane's LLM calls, leaving every other lane running — no
cross-lane serialisation needed.

Procedure:

`quaid config get/set` is deprecated; edit the layered JSON files directly.
The platform-layer config for CC lives at
`~/.quaid/shared/config/claude-code/config.json` (platform is
`claude-code` — hyphen, not underscore).

1. Record the current fast and deep reasoning model names from the platform
   config so you can restore them later:

   ```bash
   ssh REMOTE_HOST "python3 -c 'import json, pathlib
   p = pathlib.Path.home() / \".quaid/shared/config/claude-code/config.json\"
   d = json.loads(p.read_text())
   m = d.get(\"models\", {})
   print(\"fast:\", m.get(\"fastReasoning\"))
   print(\"deep:\", m.get(\"deepReasoning\"))'"
   ```

2. Write the sentinel names into the platform config (deep-merge, preserve
   everything else):

   ```bash
   ssh REMOTE_HOST "python3 -c 'import json, pathlib
   p = pathlib.Path.home() / \".quaid/shared/config/claude-code/config.json\"
   d = json.loads(p.read_text())
   d.setdefault(\"models\", {})[\"fastReasoning\"] = \"invalid-model-m6-probe\"
   d[\"models\"][\"deepReasoning\"] = \"invalid-model-m6-probe\"
   p.write_text(json.dumps(d, indent=2))
   print(\"set\")'"
   ```

   Bounce the daemon so the new values are loaded:

   ```bash
   ssh REMOTE_HOST "source ~/.zprofile; QUAID_HOME=~/.quaid QUAID_INSTANCE=\$INSTANCE \
     \$QCLI daemon stop; sleep 2; QUAID_HOME=~/.quaid QUAID_INSTANCE=\$INSTANCE \$QCLI daemon start"
   ```

3. Send a user turn that requires an LLM call (a recall that triggers deep
   reasoning, or any extraction-path turn).

4. Verify the provider error message appears in the agent's injected context
   that turn.

5. Send a second identical turn. Verify the error fires AGAIN, not
   suppressed.

6. Send a third turn. Still fires — no dedupe on actively-firing errors.

7. Restore the original models into the same platform config:

   ```bash
   ssh REMOTE_HOST "python3 -c 'import json, pathlib
   p = pathlib.Path.home() / \".quaid/shared/config/claude-code/config.json\"
   d = json.loads(p.read_text())
   d[\"models\"][\"fastReasoning\"] = \"<original-fast>\"
   d[\"models\"][\"deepReasoning\"] = \"<original-deep>\"
   p.write_text(json.dumps(d, indent=2))
   print(\"restored\")'"
   ```

   Bounce the daemon again so the restore takes effect.

8. Verify clean recovery on the next turn — no provider-error notice
   injected, recall behaves normally.

## PWN vs FAIL

- Part A dedupe turn still has the notice but phrased differently — PWN if
  the system clearly attempted dedup; FAIL if dedupe logic is totally absent.
- Part B error notice fires only on the first turn then disappears while
  config is still broken — FAIL (dedupe of an actively-firing error is the
  explicit anti-pattern).
- Cross-session bleed (Part A notice intended for session X appears in
  session Y) — FAIL.
- On restore (Part B step 7), the agent still shows provider-error injected
  content — FAIL; means restore didn't clear.
