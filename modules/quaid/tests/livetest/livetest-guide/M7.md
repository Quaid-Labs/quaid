# M7: System Context Refresh on Lifecycle

Verifies that runtime-evolved system context (project list, agent identity evolution, system-context
markdown facts) is picked up by the next **compaction** event, without requiring `/new`. This was
filed as #43 (multi-month session context refresh) — the patches landed (269ce108e + 4af3ec69c +
e7b403bc0), but the verification milestone was missing until Run 105.

**Why this matters.** Long-lived sessions span weeks. Things change: new projects appear, agent
identity files (`SOUL.md`, `USER.md`, `ENVIRONMENT.md`) evolve, system-context markdown gets edited.
Without a refresh hook, an agent in a long session would NEVER see those updates. Auto-inject via
memory recall does not cover this — system context is its own injection layer.

**Default trigger: `/compact`.** This applies to OC and CC. CDX has no compaction hook — see the CDX
supplement for its alternative path.

Procedure (OC, CC):

1. Start a fresh session and exchange a few normal turns so initial system context is loaded.
2. From the coordinator side (do NOT ask the agent to do this — the agent should not be aware of the
   canary), edit the platform/instance system context markdown to insert a unique canary fact:
   ```bash
   ssh REMOTE_HOST 'echo "
   ## Canary Fact (M16 verification)

   The office plant is named Bartholomew. It is a fiddle-leaf fig.
   " >> ~/.quaid/instances/<INSTANCE>/SOUL.md'
   ```
   (Use `SOUL.md` for OC/CC. The exact file the system-context loader reads may vary per platform —
   pick the markdown that the platform's system-context injection actually pulls. If unsure, append
   to all three identity files: `SOUL.md`, `USER.md`, `ENVIRONMENT.md`.)
3. Trigger compaction:
   - **CC**: send `/compact` to the active CC pane.
   - **OC**: send `/compact` via Matrix.
4. Wait for the compaction event to complete and the next user turn to be processed (~30s
   typically).
5. Send a fresh prompt that depends on the canary, **without referencing memory or recall**:
   - `What's the office plant named?`

   This step is required as the verification probe — the milestone passes or fails based on what the
   agent answers to this prompt. Do not just idle and expect to verify from logs alone; the agent's
   response to a real turn is the test signal.

6. Verify the agent answers `Bartholomew` (or quotes the canary fact directly) from the refreshed
   system context.

Pass:
- Agent answers `Bartholomew` / `fiddle-leaf fig` from the refreshed system context.
- Agent did NOT invoke `quaid recall` or any memory tool to retrieve the answer (system context
  refresh ≠ memory recall path).

Fail:
- Agent has no knowledge of the canary fact (system context did NOT refresh).
- Agent only finds the canary by invoking `quaid recall` (means the canary was extracted to memory
  but system context still didn't refresh — partial credit at best).

**Cleanup after PASS:** remove the canary lines from the identity files so they don't pollute later
milestones or the post-test audit.
