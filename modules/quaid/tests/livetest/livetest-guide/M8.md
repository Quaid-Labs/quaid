# M8: Temporal Provenance

Purpose: validate that Quaid distinguishes WHEN a fact OCCURRED, when it was
MENTIONED, and when its row was RECORDED — and that recall date filters can
target each axis independently. This milestone exercises the temporal
provenance feature added in checkpoint commits 55250e34c
(`feat(recall): add temporal provenance fields`) and 99d8bcd76
(`feat(recall): route date filters by temporal provenance`).

Depends on the temporal-provenance lineage being present on the install:
- `nodes` table has `occurred_start`, `occurred_end`, `mentioned_at` columns
- `memory_graph.recall(...)` accepts `temporal_dimension` kwarg
- `ingest/extract.py` populates the three axes distinctly

Run after M3 in the natural milestone order so previous recall behavior is
already known clean.

## Setup

Pick the lane's instance and the standard `$QCLI` / `$INSTANCE` / `$SILO`
variables. Create an artifact directory:

```bash
LANE_UPPER=$(printf "%s" "$LANE" | tr '[:lower:]' '[:upper:]')
PROBE_ID="M8-${LANE_UPPER}-TEMPORAL-$(date +%Y%m%d-%H%M%S)"
ART="$HOME/m8-artifacts/$PROBE_ID"
mkdir -p "$ART"
echo "$PROBE_ID"  > "$ART/probe-id.txt"
```

If this milestone requires a janitor apply before or after temporal probes, use
the current CLI shape:

```bash
ssh REMOTE_HOST "$QCLI janitor --task all --apply"
```

Do not use the obsolete `quaid janitor run --apply` form; current installs reject
the extra `run` argument.

## Seed

Two natural-language seed facts that distinguish the three axes:

- **Old-event fact**: a fact about an event that OCCURRED in the past but is
  MENTIONED today. Example user message sent today: *"Back in May 2023 I
  attended a leatherworking workshop in Kyoto led by Mura Sensei."*
  Expected DB row after extraction:
  - `occurred_start ≈ 2023-05-01` (or month-bounded range)
  - `mentioned_at ≈ <today>`
  - `created_at ≈ <today>` (record axis)
- **Now-event fact**: a fact about something happening now, also mentioned
  in the same conversation. Example: *"I started using a 14mm Sailor
  Pro Gear nib this week for my journal."*
  Expected DB row:
  - `occurred_start ≈ <today>` (or this-week range)
  - `mentioned_at ≈ <today>`
  - `created_at ≈ <today>`

Send both via the lane's normal extraction path (matrix for OC, visible CC
pane, visible CDX pane), trigger lifecycle (`/clear`, `/new`, `/reset`), and
wait the rolling poll window until extraction lands.

Verify the rows landed with distinct temporal axes:

```bash
ssh REMOTE_HOST "sqlite3 \$HOME/.quaid/instances/\$INSTANCE/data/memory.db \
  \"SELECT id, substr(name,1,60), occurred_start, occurred_end, mentioned_at, \
  created_at FROM nodes WHERE name LIKE '%leatherworking%' OR name LIKE '%Sailor Pro Gear%'\""
```

If the install does NOT have `ingest/extract.py` populating temporal fields
(checkpoint feature not folded into dev tree), seed manually via SQL with
explicit values for the recall probes — note this in the artifact and
classify the run as "recall-only validation":

```bash
ssh REMOTE_HOST "sqlite3 \$HOME/.quaid/instances/\$INSTANCE/data/memory.db \
  \"UPDATE nodes SET occurred_start='2023-05-01', occurred_end='2023-05-31', \
  mentioned_at=date('now') WHERE name LIKE '%leatherworking%'\""
```

## Part A — Extraction populates distinct axes

Probe: send a fresh transcript turn that mentions an old-dated event.
Verify post-extraction the resulting node has:
- `occurred_start` / `occurred_end` matching the in-text date
- `mentioned_at` close to current time
- `created_at` close to current time
- NOT all three set to the same value

Pass: at least one extracted fact has `occurred_start` distinct from
`mentioned_at` (more than 1 day apart, in the natural direction old < now).

Fail: all three columns share the same value, or `occurred_start` is null
for an explicit old-dated event.

## Part B — `temporal_dimension=occurred` returns old-event facts

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"2023-01-01\",\"date_to\":\"2023-12-31\", \
  \"temporal_dimension\":\"occurred\"}'"
```

Pass: the leatherworking row appears in the top results.

Fail: empty result set OR the today-dated `Sailor Pro Gear` fact appears
(which would indicate the filter ran on the wrong axis).

## Part C — `temporal_dimension=mentioned` is distinct from occurred

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"2023-01-01\",\"date_to\":\"2023-12-31\", \
  \"temporal_dimension\":\"mentioned\"}'"
```

Pass: the leatherworking row does NOT appear (it was mentioned today, not in
2023). A second probe with mentioned-axis bounds matching today MUST return
the leatherworking row:

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"$(date -u +%Y-%m-%d)\",\"date_to\":\"$(date -u +%Y-%m-%d)\", \
  \"temporal_dimension\":\"mentioned\"}'"
```

Fail: leatherworking row appears under the 2023 mentioned-axis probe (axis
collapse), OR the today-mentioned probe misses it.

## Part D — `temporal_dimension=record` (created_at) behaves separately

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"$(date -u +%Y-%m-%d)\",\"date_to\":\"$(date -u +%Y-%m-%d)\", \
  \"temporal_dimension\":\"record\"}'"
```

Pass: row appears under today's record-axis bound (it was created today)
AND does NOT appear under the 2023 record-axis bound. Confirms the record
axis is wired separately from occurred and mentioned.

Aliases to spot-check (`created_at` should map to `record`):

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"$(date -u +%Y-%m-%d)\",\"date_to\":\"$(date -u +%Y-%m-%d)\", \
  \"temporal_dimension\":\"created_at\"}'"
```

If the alias passes but a non-canonical value (e.g. `recorded_at`, `record_at`)
fails, that's PWN-note, not FAIL.

## Part E — Legacy rows with no occurrence fields fall back safely

Pre-temporal-feature rows have NULL `occurred_start` / `occurred_end` /
`mentioned_at`. They should NOT crash the recall query; they should fall
back to the `record` axis (created_at) under `auto`, and they should be
gracefully excluded under explicit `occurred` / `mentioned` filters when
the corresponding axis is NULL.

```bash
# Pick a legacy row known to predate the temporal feature (M2 brass postal
# scale row from an earlier run is a good candidate). Verify its temporal
# columns are NULL:
ssh REMOTE_HOST "sqlite3 \$HOME/.quaid/instances/\$INSTANCE/data/memory.db \
  \"SELECT id, occurred_start, occurred_end, mentioned_at, created_at \
  FROM nodes WHERE name LIKE '%brass postal%' LIMIT 1\""

# Recall under occurred filter — legacy row must NOT crash, MUST be omitted:
ssh REMOTE_HOST "\$QCLI recall 'brass postal scale' \
  '{\"date_from\":\"2023-01-01\",\"date_to\":\"2023-12-31\", \
  \"temporal_dimension\":\"occurred\"}'"
```

Pass: query completes without error; legacy row is omitted from results
(because its `occurred_start` is NULL, no match for the date range).

Fail: query crashes with NullType comparison error, OR returns the legacy
row under an `occurred` filter when its `occurred_start` is NULL.

## Part F — `fail_hard=true` surfaces extraction/recall failures loudly

Quaid's `retrieval.fail_hard=true` (the livetest default) means temporal
filter mistakes must raise loudly, not silently degrade.

Probe: pass an invalid `temporal_dimension`:

```bash
ssh REMOTE_HOST "\$QCLI recall 'leatherworking workshop' \
  '{\"date_from\":\"2023-01-01\",\"date_to\":\"2023-12-31\", \
  \"temporal_dimension\":\"banana\"}' 2>&1"
```

Pass: command exits non-zero with a `ValueError` or `RuntimeError` about
`temporal_dimension must be one of auto, occurred, mentioned, or record`.

Fail: command silently coerces `banana` to a default and returns results
without surfacing the error.

A second failHard probe: corrupt one row's `occurred_start` to a malformed
string (`'not-a-date'`) and confirm a recall under `temporal_dimension=occurred`
either raises (preferred under failHard) or silently excludes the bad row
without crashing on subsequent rows. Restore after.

## Common PWN vs FAIL notes

- Extraction-side temporal axes not populated because the install's
  `ingest/extract.py` predates the feature → milestone is RECALL-ONLY for
  the run; document the gap and proceed with seeded probes. PWN-note, not
  FAIL.
- Alias `created_at` works but `recorded_at` fails → PWN-note.
- `auto` dimension's exact axis precedence undocumented for a row with all
  three set → PWN-note unless behavior contradicts the docstring.
- Legacy row crashes under `occurred` filter → FAIL.
- `temporal_dimension=banana` silently accepted → FAIL.
- `temporal_dimension=mentioned` returning rows that match `occurred` axis
  → FAIL (axis collapse).
