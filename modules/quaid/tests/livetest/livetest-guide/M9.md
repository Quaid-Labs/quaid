# M9: Session Chunk Navigation

Purpose: validate that raw session evidence is stored as `session_chunks`, can be
searched directly, and can be expanded by linked-list navigation without flooding
recall output.

Depends on dev SHA containing:
- `session_chunks` store name in recall plans
- `source_chunks` table with `session_id`, `next_chunk_id`, `message_id`, `message_pair_id`, and `embedding`
- public Python functions `store_session_chunk(s)`, `list_session_chunks`, and `get_session_chunk`

Run after M8 or after a fresh deploy of the session-chunk framework.

## Setup

Coordinator brief note: `REMOTE_HOST` must be the VM SSH address from the
current run config (for example, `admin@192.168.64.209` for Run 184). Do not use
`alfie.local` or any local mDNS hostname; tester boxes can resolve that name to
the coordinator machine instead of the VM under test.

```bash
LANE_UPPER=$(printf "%s" "$LANE" | tr '[:lower:]' '[:upper:]')
PROBE_ID="M9-${LANE_UPPER}-SESSION-CHUNKS-$(date +%Y%m%d-%H%M%S)"
```

## Seed

Use the product Python API against the lane's installed Quaid, not raw SQL:

```bash
ssh REMOTE_HOST "PYTHONPATH=\$HOME/.quaid/plugins/quaid/modules/quaid python3 - <<'PY'
from datastore.memorydb.memory_graph import get_graph

g = get_graph()
rows = g.store_session_chunks(
    [
        'User: I keep the red travel notebook in the cedar desk. Assistant: Noted.',
        'User: The notebook has the Lisbon ferry receipt tucked inside. Assistant: Got it.',
        'User: If I ask for the ferry receipt later, remind me it is in the red notebook.',
    ],
    owner_id='solomon-steadman',
    session_id='m9-session-linked',
    source_id='m9-session-linked',
    message_pair_id='m9-pair-notebook',
    chunk_kind='micro',
)
print('\n'.join(r['chunk_id'] for r in rows))
PY" | tee "$ART/seed-chunk-ids.txt"
```

## Part A — schema and scalar linkage

```bash
ssh REMOTE_HOST "sqlite3 \$HOME/.quaid/instances/\$INSTANCE/data/memory.db \
  \"SELECT chunk_index, session_id, chunk_kind, message_pair_id, next_chunk_id IS NOT NULL \
  FROM source_chunks WHERE session_id='m9-session-linked' ORDER BY chunk_index\"" | tee "$ART/part-a-schema.txt"
```

Pass: three rows, all have `session_id=m9-session-linked`; first two have a next
chunk; last has no next chunk.

Fail: missing `session_id`, missing scalar columns, or no navigable `next_chunk_id`.

## Part B — direct `session_chunks` recall

```bash
ssh REMOTE_HOST "\$QCLI recall 'where is the Lisbon ferry receipt' \
  '{\"stores\":[\"session_chunks\"],\"limit\":3,\"max_chunk_tokens\":80}' --json" \
  | tee "$ART/part-b-session-recall.json"
```

Pass: a `session_chunk` result appears, includes `chunk_id`/`session_chunk_id`,
`session_id=m9-session-linked`, and text mentioning the ferry receipt or red
notebook.

Fail: no session chunk row, wrong owner/session, or result only comes from vector facts.

## Part D — fetch by id and expand window

Use the top chunk id from Part B/C:

```bash
CHUNK_ID=$(python3 - <<'PY' "$ART/part-b-session-recall.json"
import json, sys
payload=json.load(open(sys.argv[1]))
rows=payload.get('results') if isinstance(payload, dict) else payload
print((rows or [{}])[0].get('chunk_id') or (rows or [{}])[0].get('session_chunk_id') or '')
PY
)
ssh REMOTE_HOST "PYTHONPATH=\$HOME/.quaid/plugins/quaid/modules/quaid python3 - <<PY
from datastore.memorydb.memory_graph import get_session_chunk
row = get_session_chunk('$CHUNK_ID', owner_id='solomon-steadman', before=1, after=1)
print(row['chunk_id'])
print([r['chunk_index'] for r in row.get('window', [])])
print([r['chunk_id'] for r in row.get('window', [])])
PY" | tee "$ART/part-d-window.txt"
```

Pass: fetch returns the center chunk and adjacent linked chunks in order.

Fail: no fetch surface, wrong owner allowed, or window cannot move across links.

## Part F — SessionDB bridge: pair chain and microchunk cross-reference

> Run after M2 Part B recheck has settled. No new seeds — this observes the real
> extraction rows that M2 produced. Verifies: session.db was created, SessionDB
> pair chain integrity, microchunks at ≤40-token scale, and MemoryDB carries
> microchunk_id / message_pair_id cross-references.

Discover the session.db path for this lane's installed Quaid:

```bash
SESSION_DB=$(ssh "$REMOTE_HOST" "PYTHONPATH=\$HOME/.quaid/plugins/quaid/modules/quaid \
  QUAID_HOME=~/.quaid QUAID_INSTANCE=$INSTANCE python3 -c '
from lib.config import get_session_db_path
print(get_session_db_path())
'" 2>/dev/null)
echo "session.db: $SESSION_DB" | tee "$ART/part-f-session-db-path.txt"
```

### F1 — session.db exists

```bash
ssh "$REMOTE_HOST" "test -f '$SESSION_DB' && echo EXISTS || echo MISSING" \
  | tee "$ART/part-f-f1-exists.txt"
```

Pass: `EXISTS`.
Fail: `MISSING` — daemon workers loaded before hot-deploy hold the old `extract.py`.
Bounce the daemon (`quaid daemon stop && quaid daemon start` for each instance),
trigger one extraction turn, then recheck.

### F2 — session_pairs and session_microchunks populated

Find the most recently written session and verify rows in both tables:

```bash
LAST_SID=$(ssh "$REMOTE_HOST" "sqlite3 '$SESSION_DB' \
  'SELECT session_id FROM session_pairs ORDER BY created_at DESC LIMIT 1'" 2>/dev/null)
echo "last session_id: $LAST_SID" | tee "$ART/part-f-f2-session-id.txt"

ssh "$REMOTE_HOST" "sqlite3 '$SESSION_DB' \"
SELECT 'pairs',      count(*) FROM session_pairs      WHERE session_id='$LAST_SID';
SELECT 'microchunks',count(*) FROM session_microchunks WHERE session_id='$LAST_SID';
\"" | tee "$ART/part-f-f2-counts.txt"
```

Pass: `pairs ≥ 1` and `microchunks ≥ 1`.
Fail: either count = 0 — bridge write path did not fire for this lane.

### F3 — microchunk token scale (≤40 tokens ≈ ≤200 chars)

```bash
ssh "$REMOTE_HOST" "sqlite3 '$SESSION_DB' \"
SELECT max(length(text)), avg(length(text))
FROM session_microchunks WHERE session_id='$LAST_SID'
\"" | tee "$ART/part-f-f3-microchunk-lengths.txt"
```

Pass: max ≤ 200.
Fail: max > 500 — `DEFAULT_SESSION_MICROCHUNK_TOKENS` has regressed back toward the
legacy 1200-token window; route to W1.

### F4 — pair chain integrity (exactly one tail)

Each session must have exactly one pair with `next_pair_id IS NULL` (the tail).

```bash
ssh "$REMOTE_HOST" "sqlite3 '$SESSION_DB' \"
SELECT count(*) FROM session_pairs
WHERE session_id='$LAST_SID' AND next_pair_id IS NULL
\"" | tee "$ART/part-f-f4-chain-tail.txt"
```

Pass: count = 1.
Fail: count > 1 — multi-tail invariant broken; `store_session_source_text` would raise
`RuntimeError: session pair chain has multiple tails` on the next write. Route W1 urgent.
Fail: count = 0 — every pair has a forward pointer (impossible unless schema corruption).

### F5 — MemoryDB cross-references carry microchunk_id and message_pair_id

```bash
MEMORY_DB="$HOME/.quaid/instances/$INSTANCE/data/memory.db"
ssh "$REMOTE_HOST" "sqlite3 '$MEMORY_DB' \"
SELECT count(*) FROM source_chunks
WHERE session_id='$LAST_SID'
  AND microchunk_id IS NOT NULL
  AND message_pair_id IS NOT NULL
\"" | tee "$ART/part-f-f5-xref.txt"
```

Pass: count ≥ 1 — MemoryDB rows carry both cross-reference fields.
Fail: count = 0 — `attach_memory_chunk` step in bridge did not link rows, or
MemoryDB `store_session_chunks` call is not receiving `microchunk_ids`/`message_pair_ids`.
Route W1 with `part-f-f2-counts.txt` and `part-f-f5-xref.txt`.

### F6 — expand a microchunk via CLI

Use the first `microchunk_id` from MemoryDB to drive a recall expand:

```bash
MC_ID=$(ssh "$REMOTE_HOST" "sqlite3 '$MEMORY_DB' \"
SELECT microchunk_id FROM source_chunks
WHERE session_id='$LAST_SID' AND microchunk_id IS NOT NULL LIMIT 1
\"" 2>/dev/null)
echo "microchunk_id: $MC_ID" | tee "$ART/part-f-f6-mcid.txt"

ssh "$REMOTE_HOST" "QUAID_INSTANCE=$INSTANCE \$QCLI session expand-microchunk '$MC_ID' 2>&1" \
  | tee "$ART/part-f-f6-expand.txt"
```

Pass: output includes the expanded pair text (user + assistant turn) without error.
Fail: command not found or empty output — `expand_microchunk` bridge route not wired.
