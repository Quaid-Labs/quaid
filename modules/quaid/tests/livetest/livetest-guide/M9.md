# M9: Session Chunk Navigation

Purpose: validate that raw session evidence is stored as `session_chunks`, can be
searched directly, and can be expanded by linked-list navigation without flooding
recall output.

Depends on dev SHA containing:
- `session_chunks` store name in recall plans
- `source_chunks` table with `session_id`, `next_chunk_id`, `message_id`, `message_pair_id`, and `embedding`
- public Python functions `store_session_chunk(s)`, `list_session_chunks`, and `get_session_chunk`

Run after M8 or after a fresh deploy of the session-chunk framework.

## Setup

```bash
LANE_UPPER=$(printf "%s" "$LANE" | tr '[:lower:]' '[:upper:]')
PROBE_ID="M9-${LANE_UPPER}-SESSION-CHUNKS-$(date +%Y%m%d-%H%M%S)"
ART="$HOME/m9-artifacts/$PROBE_ID"
mkdir -p "$ART"
echo "$PROBE_ID" > "$ART/probe-id.txt"
```

## Seed

Use the product Python API against the lane's installed Quaid, not raw SQL:

```bash
ssh REMOTE_HOST "PYTHONPATH=\$HOME/.quaid/plugins/quaid/modules/quaid python3 - <<'PY'
from datastore.memorydb.memory_graph import get_graph

g = get_graph()
rows = g.store_session_chunks(
    [
        'User: I keep the red travel notebook in the cedar desk. Assistant: Noted.',
        'User: The notebook has the Lisbon ferry receipt tucked inside. Assistant: Got it.',
        'User: If I ask for the ferry receipt later, remind me it is in the red notebook.',
    ],
    owner_id='solomon-steadman',
    session_id='m9-session-linked',
    source_id='m9-session-linked',
    message_pair_id='m9-pair-notebook',
    chunk_kind='micro',
)
print('\n'.join(r['chunk_id'] for r in rows))
PY" | tee "$ART/seed-chunk-ids.txt"
```

## Part A — schema and scalar linkage

```bash
ssh REMOTE_HOST "sqlite3 \$HOME/.quaid/instances/\$INSTANCE/data/memory.db \
  \"SELECT chunk_index, session_id, chunk_kind, message_pair_id, next_chunk_id IS NOT NULL \
  FROM source_chunks WHERE session_id='m9-session-linked' ORDER BY chunk_index\"" | tee "$ART/part-a-schema.txt"
```

Pass: three rows, all have `session_id=m9-session-linked`; first two have a next
chunk; last has no next chunk.

Fail: missing `session_id`, missing scalar columns, or no navigable `next_chunk_id`.

## Part B — direct `session_chunks` recall

```bash
ssh REMOTE_HOST "\$QCLI recall 'where is the Lisbon ferry receipt' \
  '{\"stores\":[\"session_chunks\"],\"limit\":3,\"max_chunk_tokens\":80}' --json" \
  | tee "$ART/part-b-session-recall.json"
```

Pass: a `session_chunk` result appears, includes `chunk_id`/`session_chunk_id`,
`session_id=m9-session-linked`, and text mentioning the ferry receipt or red
notebook.

Fail: no session chunk row, wrong owner/session, or result only comes from vector facts.

## Part C — semantic chunk search

```bash
ssh REMOTE_HOST "\$QCLI recall 'proof of boat crossing purchase location' \
  '{\"stores\":[\"session_chunks\"],\"limit\":3,\"max_chunk_tokens\":80}' --json" \
  | tee "$ART/part-c-semantic-recall.json"
```

Pass: the ferry receipt chunk is returned even if exact words differ; telemetry
shows semantic or mixed chunk matching when exposed.

Fail: only exact lexical matches work.

## Part D — fetch by id and expand window

Use the top chunk id from Part B/C:

```bash
CHUNK_ID=$(python3 - <<'PY' "$ART/part-b-session-recall.json"
import json, sys
payload=json.load(open(sys.argv[1]))
rows=payload.get('results') if isinstance(payload, dict) else payload
print((rows or [{}])[0].get('chunk_id') or (rows or [{}])[0].get('session_chunk_id') or '')
PY
)
ssh REMOTE_HOST "PYTHONPATH=\$HOME/.quaid/plugins/quaid/modules/quaid python3 - <<PY
from datastore.memorydb.memory_graph import get_session_chunk
row = get_session_chunk('$CHUNK_ID', owner_id='solomon-steadman', before=1, after=1)
print(row['chunk_id'])
print([r['chunk_index'] for r in row.get('window', [])])
print([r['chunk_id'] for r in row.get('window', [])])
PY" | tee "$ART/part-d-window.txt"
```

Pass: fetch returns the center chunk and adjacent linked chunks in order.

Fail: no fetch surface, wrong owner allowed, or window cannot move across links.

## Part E — mixed vector + session_chunks RRF

```bash
ssh REMOTE_HOST "\$QCLI recall 'Lisbon ferry receipt notebook' \
  '{\"stores\":[\"vector\",\"session_chunks\"],\"limit\":5,\"max_chunk_tokens\":80}' --json" \
  | tee "$ART/part-e-rrf.json"
```

Pass: query completes under failHard and meta includes active RRF or shadow RRF
for `vector` + `session_chunks`; session chunks remain bounded.

Fail: mixed store plan errors, silently drops `session_chunks`, or floods output
with large transcript text.
